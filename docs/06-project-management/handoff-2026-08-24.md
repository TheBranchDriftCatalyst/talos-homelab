## Things that will bite you if you don't know them

### Applying machine config REBOOTS the node

Bisected to a single cause: talhelper must remove `machine.features.stableHostname`, because
Talos rejects it coexisting with the `HostnameConfig` document talhelper emits — and Talos
classifies that removal as reboot-required. Every other change applies without a reboot.

### `module.sig_enforce=0` silently fails

Talos appends extra kernel args *after* defaults, with overwrite enabled for only `console`
and `talos.platform`. Both `=1` and `=0` land on the cmdline and the kernel refuses the
downgrade with `-EROFS`. **Use the negation:** `-module.sig_enforce`. Verify by ABSENCE of the
token in `/proc/cmdline`.

### talhelper applies GLOBAL patches AFTER per-node ones

So a per-node override of a globally-declared value **silently loses**. This was resetting
talos03's `maxPods`. Anything a node needs to differ on must not appear in a global patch at
all. The CI lint now catches this — and was negative-tested to prove it fires.

### `etcd members` is the wrong quorum signal

It reports *configured* membership, which stays at 3 straight through a real quorum loss. It
gave me false comfort for two nodes. Use `kubectl auth can-i create` — that proves etcd is
**writable**, which is what quorum loss actually breaks.

### Reboots leave ~25–30 phantom `Error` pods

Pre-reboot pod objects that kubelet never reaps because the node's state was reset. Every one
has a Running replacement. **Count deployment readiness, not pod phase**, or you will chase
ghosts.

### `~/.curlrc` has `-v` and `-k` globally

Any tool on this machine that shells out to curl with credentials leaks them to stderr. This
has now caused **two** credential exposures — TALOS-1e9 (GitHub PAT, still open) and the
registry credential today. Closed as accepted risk per your call, but the pattern is proven.
Scripts should pass `-q`.

## The throughline worth carrying forward

**Almost every problem today was something reporting success while the effect was absent.**

- Flux `applied revision X` — while git no longer contained the change
- A HelmRelease `Ready` — over values a duplicate YAML key had discarded
- minio-operator `Running`, 0 restarts — while not reconciling at all
- A DaemonSet at `5/5 ready` — only because its request had been reverted
- `kustomize build` exit 0 — on a chart values key the chart does not read
- My own differ reporting "0 unresolved" — while a skip list hid `certSANs`

**When a control loop reports success and the effect is absent, verify the OUTPUT object, not
the controller's status.** Every one of these was caught by reading the live object, and none
by reading a status field.

And the corollary that cost the most: **an offline checker written by whoever wrote the config
cannot validate it.** My verification tooling was the weak link three separate times. The
things that actually found problems were `talosctl apply-config --dry-run` against a real node,
and two independent adversarial audits.
