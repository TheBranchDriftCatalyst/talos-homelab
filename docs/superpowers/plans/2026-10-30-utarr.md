# utarr Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a "utarr" applet to the Catalyst Swiss Army Knife Chrome extension that can subscribe to the current YouTube channel, subscribe to the current playlist, or queue the current video for download in Youtarr — plus the server-side route it needs and a self-hosted install/update channel.

**Architecture:** utarr is one applet inside the existing `@catalyst-swiss-army-knife` extension (already a plugin mount point with an applet router). Video download goes through Youtarr's `POST /api/videos/download`, authenticated by Traefik BasicAuth on a single bypassed path. Channel and playlist subscribe copy the URL to the clipboard and open Youtarr's `/subscriptions`, because Youtarr has no API for them. Distribution is a self-signed CRX served from the homelab plus a Chrome enterprise-policy forcelist.

**Tech Stack:** TypeScript, React 19, webpack 5, Vitest (added by this plan), go-task, Kubernetes/Flux, Traefik IngressRoute, External Secrets Operator.

**Spec:** `docs/superpowers/specs/2026-10-30-utarr-chrome-extension-design.md`

## Global Constraints

- Youtarr base URL: `https://youtarr.talos00`. Service: `youtarr:3011` in namespace `downloads`.
- The ONLY Youtarr external API endpoint is `POST /api/videos/download`. It accepts a single video URL. Playlists, channels and batch operations are NOT available via API — do not attempt them.
- Request body fields honoured: `url` (required), `resolution` (360|480|720|1080|1440|2160), `subfolder`. Any other field is ignored. Folder layout is not per-request settable.
- Auth header for the API: `Authorization: Basic ...` (Traefik BasicAuth). Youtarr itself runs `AUTH_ENABLED=false` and must stay that way — turning it on reintroduces a second login screen.
- Credentials are stored in `chrome.storage.local`, never `chrome.storage.sync`.
- HOMELAB is Flux-managed GitOps: commit and push, then `flux reconcile ... --with-source`. Never `kubectl apply` as the durable change.
- HOMELAB commits: use a private index — `export GIT_INDEX_FILE=$(mktemp); git read-tree HEAD; git add -- <paths>; git commit`. A bare `git add` can sweep in other sessions' files. `docs/07-reference/cluster-crds.md` is dirty from another session and must never be committed.
- HOMELAB commit gates: markdownlint, yamllint, kustomize-validate, kube-validate, gitleaks, conventional-commits. Markdown lines: no multiple spaces after `>`.
- Never verify a commit by reading the hook output — confirm with `git ls-tree -r HEAD --name-only | grep <file>`.
- The extension signing PEM is a SECRET. Never commit it. Losing it changes the extension ID and breaks every installed policy.

### Task 2: Generate the BasicAuth credential

Traefik's `basicAuth` needs a Secret whose `users` key holds an **htpasswd** line (hashed). The extension needs the **same password in plaintext**. So one ExternalSecret must emit both.

**Files:**
- Modify: `applications/youtarr/secret.yaml`

**Interfaces:**
- Consumes: nothing
- Produces: Secret `youtarr-api-basicauth` in namespace `downloads` with keys `users` (htpasswd line) and `password` (plaintext), username fixed as `utarr`

- [ ] **Step 1: Confirm sprig's htpasswd function is available in ESO**

ESO v2.6.0 templating exposes sprig. Sprig provides `htpasswd USER PASS`, which returns a bcrypt htpasswd entry. Verify before relying on it by applying the manifest in Step 2 and reading the resulting Secret in Step 4.

If `htpasswd` is NOT available, the template will fail and the ExternalSecret will report an error. In that case, in order:
1. Try sprig's `bcrypt` and build the line as `printf "utarr:%s" (bcrypt .password)`.
2. If neither exists, **STOP and report back** — do not hand-create the Secret. A manually created secret is not reproducible on a rebuild, and the spec says to re-open the auth decision rather than ship one.

- [ ] **Step 2: Append the generator and ExternalSecret**

Append to `applications/youtarr/secret.yaml`:

```yaml
---
# BasicAuth credential for the utarr Chrome extension (see
# docs/superpowers/specs/2026-10-30-utarr-chrome-extension-design.md).
#
# Emits BOTH halves of the same password:
#   users    - htpasswd line, consumed by the Traefik basicAuth middleware
#   password - plaintext, typed into the extension's settings by the operator
#
# refreshInterval "0" = generate once. Editing this spec re-evaluates the
# generator and ROTATES the password, which silently breaks the installed
# extension until its settings are updated. Do not edit casually.
apiVersion: generators.external-secrets.io/v1alpha1
kind: Password
metadata:
  name: youtarr-api-basicauth
  namespace: downloads
spec:
  length: 40
  digits: 10
  symbols: 0 # alphanumeric — avoids escaping issues in an Authorization header
  symbolCharacters: ""
  noUpper: false
  allowRepeat: true
---
apiVersion: external-secrets.io/v1
kind: ExternalSecret
metadata:
  name: youtarr-api-basicauth
  namespace: downloads
spec:
  refreshInterval: "0"
  target:
    name: youtarr-api-basicauth
    creationPolicy: Owner
    deletionPolicy: Retain
    template:
      engineVersion: v2
      data:
        users: "{{ htpasswd \"utarr\" .password }}"
        password: "{{ .password }}"
  dataFrom:
    - sourceRef:
        generatorRef:
          apiVersion: generators.external-secrets.io/v1alpha1
          kind: Password
          name: youtarr-api-basicauth
```

- [ ] **Step 2: Add the middleware and route**

Append to `applications/youtarr/ingressroute.yaml`:

```yaml
---
# BasicAuth for the single API path the utarr extension calls.
# Credential comes from the youtarr-api-basicauth ExternalSecret (key `users`).
apiVersion: traefik.io/v1alpha1
kind: Middleware
metadata:
  name: youtarr-api-basicauth
  namespace: downloads
spec:
  basicAuth:
    secret: youtarr-api-basicauth
---
# utarr extension API route.
#
# Path() not PathPrefix() — exactly ONE endpoint is exempted from Authentik.
# Youtarr runs AUTH_ENABLED=false, so it does NOT check the API key itself:
# upstream warns that in that mode it "accepts every request without checking
# the API key". This BasicAuth middleware is therefore the ONLY thing standing
# in front of the endpoint. Widening this match, or dropping the middleware,
# makes it openly callable by anything that can reach the ingress.
#
# priority is EXPLICIT. Traefik otherwise orders by rule length, which is too
# implicit for a security boundary: if the Authentik route won, the extension
# would silently 302 instead of working.
apiVersion: traefik.io/v1alpha1
kind: IngressRoute
metadata:
  name: youtarr-api
  namespace: downloads
  labels:
    app: youtarr
spec:
  entryPoints:
    - websecure
  routes:
    - match: Host(`youtarr.talos00`) && Path(`/api/videos/download`)
      kind: Rule
      priority: 3000
      middlewares:
        - name: lan-only
          namespace: traefik
        - name: youtarr-api-basicauth
      services:
        - name: youtarr
          port: 3011
```

Create `src/applets/utarr/detect.ts`:

```ts
export type TargetKind = "video" | "channel" | "playlist" | "unknown";

export interface Target {
  kind: TargetKind;
  id: string | null;
  url: string;
  /** Present when a watch URL also carries ?list= */
  playlistId?: string;
}

const YT_HOST = /^(?:.+\.)?youtube\.com$/i;
const SHORT_HOST = /^youtu\.be$/i;
/** /shorts/<id>, /live/<id>, /embed/<id> */
const PATH_VIDEO = /^\/(?:shorts|live|embed)\/([^/?#]+)/;
/** /@handle, /channel/<id>, /c/<name>, /user/<name> */
const PATH_CHANNEL = /^\/(?:@[^/?#]+|channel\/[^/?#]+|c\/[^/?#]+|user\/[^/?#]+)/;

function unknown(url: string): Target {
  return { kind: "unknown", id: null, url };
}

export function detect(rawUrl: string): Target {
  let u: URL;
  try {
    u = new URL(rawUrl);
  } catch {
    return unknown(rawUrl);
  }

  if (SHORT_HOST.test(u.hostname)) {
    const id = u.pathname.slice(1).split("/")[0];
    return id ? { kind: "video", id, url: rawUrl } : unknown(rawUrl);
  }

  if (!YT_HOST.test(u.hostname)) return unknown(rawUrl);

  // A watch URL is a video even when it carries ?list= — the API ignores the
  // playlist part, so we match that behaviour and surface the list separately.
  const v = u.searchParams.get("v");
  if (u.pathname === "/watch" && v) {
    const list = u.searchParams.get("list");
    return list
      ? { kind: "video", id: v, url: rawUrl, playlistId: list }
      : { kind: "video", id: v, url: rawUrl };
  }

  const pv = PATH_VIDEO.exec(u.pathname);
  if (pv) return { kind: "video", id: pv[1], url: rawUrl };

  if (u.pathname === "/playlist") {
    const list = u.searchParams.get("list");
    return list ? { kind: "playlist", id: list, url: rawUrl } : unknown(rawUrl);
  }

  if (PATH_CHANNEL.test(u.pathname)) {
    return { kind: "channel", id: u.pathname.slice(1), url: rawUrl };
  }

  return unknown(rawUrl);
}
```

```ts
export interface UtarrSettings {
  baseUrl: string;
  username: string;
  password: string;
  subfolder: string;
  resolution: string;
}

export type DownloadResult =
  | { ok: true; message: string }
  | { ok: false; message: string };

/**
 * Queue a single video. This is the ONLY endpoint Youtarr exposes externally —
 * channels and playlists have no API and must go through its web UI.
 */
export async function downloadVideo(
  url: string,
  s: UtarrSettings,
  fetchImpl: typeof fetch = fetch
): Promise<DownloadResult> {
  const endpoint = `${s.baseUrl.replace(/\/+$/, "")}/api/videos/download`;
  const body: Record<string, string> = { url };
  if (s.subfolder) body.subfolder = s.subfolder;
  if (s.resolution) body.resolution = s.resolution;

  let res: Response;
  try {
    res = await fetchImpl(endpoint, {
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        Authorization: "Basic " + btoa(`${s.username}:${s.password}`),
      },
      body: JSON.stringify(body),
    });
  } catch {
    return { ok: false, message: `Cannot reach Youtarr at ${s.baseUrl}` };
  }

  // Landing on the SSO host means the BasicAuth route did not match and the
  // request fell through to the Authentik-gated catch-all.
  if (res.redirected && /\/application\/o\/authorize/.test(res.url)) {
    return {
      ok: false,
      message: "API route not reachable — is the Traefik bypass deployed?",
    };
  }

  if (res.status === 401 || res.status === 403) {
    return { ok: false, message: "Check your credentials in Settings" };
  }
  if (res.status === 429) {
    return { ok: false, message: "Youtarr rate limit hit — try again shortly" };
  }
  if (!res.ok) {
    return { ok: false, message: `Youtarr returned ${res.status}` };
  }
  return { ok: true, message: "Queued for download" };
}
```

```ts
const KEY = "utarr.settings";

export const DEFAULT_SETTINGS: UtarrSettings = {
  baseUrl: "https://youtarr.talos00",
  username: "",
  password: "",
  subfolder: "",
  resolution: "",
};

 * storage.local, NOT storage.sync — sync would replicate the BasicAuth
 * credential through the user's Google account.

export async function loadSettings(): Promise<UtarrSettings> {
  const got = await chrome.storage.local.get(KEY);

}

export async function saveSettings(s: UtarrSettings): Promise<void> {
  await chrome.storage.local.set({ [KEY]: s });
}
```

```tsx
const SUBSCRIPTIONS_PATH = "/subscriptions";

async function activeTabUrl(): Promise<string> {
  const [tab] = await chrome.tabs.query({ active: true, currentWindow: true });
  return tab?.url ?? "";
}

/**
 * Youtarr's add dialogs cannot be pre-filled from a URL — its SPA reads only
 * ?v and ?job. So we put the URL on the clipboard and open the page; the user
 * pastes. Automating the paste with a content script was considered and
 * rejected: it couples to Youtarr's DOM and breaks silently on its weekly
 * releases.
 */
async function handoffToYoutarr(url: string, baseUrl: string): Promise<void> {
  await navigator.clipboard.writeText(url);
  await chrome.tabs.create({ url: `${baseUrl.replace(/\/+$/, "")}${SUBSCRIPTIONS_PATH}` });
}

const Utarr: React.FC = () => {

  const [target, setTarget] = useState<Target | null>(null);
  const [status, setStatus] = useState<string>("");
  const [busy, setBusy] = useState(false);

  useEffect(() => {
    void (async () => {
      setSettings(await loadSettings());
      setTarget(detect(await activeTabUrl()));
    })();
  }, []);

  if (!settings || !target) return <div style={{ padding: 12 }}>Loading…</div>;

  const needsCreds = !settings.username || !settings.password;

  const onDownload = async () => {
    setBusy(true);
    setStatus("");
    const r = await downloadVideo(target.url, settings);
    setStatus(r.message);
    setBusy(false);
  };

  return (
    <div style={{ padding: 12, minWidth: 260, fontFamily: "system-ui, sans-serif" }}>
      <h3 style={{ margin: "0 0 8px" }}>utarr</h3>

      {target.kind === "video" && (
        <>
          <button disabled={busy || needsCreds} onClick={onDownload} style={{ width: "100%" }}>
            {busy ? "Queueing…" : "Download this video"}
          </button>
          {needsCreds && (
            <p style={{ fontSize: 12, color: "#b26a00" }}>
              Set your Youtarr credentials in the extension options first.{" "}
              <a href="#" onClick={() => chrome.runtime.openOptionsPage()}>Open settings</a>
            </p>
          )}
          {target.playlistId && (
            <button
              style={{ width: "100%", marginTop: 6 }}
              onClick={() => handoffToYoutarr(
                `https://www.youtube.com/playlist?list=${target.playlistId}`,
                settings.baseUrl
              )}
            >
              Subscribe to this playlist
            </button>
          )}
        </>
      )}

      {target.kind === "channel" && (
        <button style={{ width: "100%" }} onClick={() => handoffToYoutarr(target.url, settings.baseUrl)}>
          Subscribe to this channel
        </button>
      )}

      {target.kind === "playlist" && (
        <button style={{ width: "100%" }} onClick={() => handoffToYoutarr(target.url, settings.baseUrl)}>
          Subscribe to this playlist
        </button>
      )}

      {target.kind === "unknown" && (
        <p style={{ fontSize: 13, margin: 0 }}>
          Open a YouTube video, channel or playlist to use utarr.
        </p>
      )}

      {(target.kind === "channel" || target.kind === "playlist") && (
        <p style={{ fontSize: 11, color: "#666", marginBottom: 0 }}>
          URL copied — paste it into Youtarr&apos;s add box.
        </p>
      )}

    </div>
  );
};

export default Utarr;
```

Create `infrastructure/base/utarr-dist/deployment.yaml`:

```yaml
---
# Static host for the self-signed utarr CRX and its update manifest.
# Deliberately NOT behind Authentik: Chrome fetches updates headlessly and
# cannot complete an SSO redirect. `lan-only` is the access control.
apiVersion: v1
kind: ConfigMap
metadata:
  name: utarr-dist-nginx
  namespace: downloads
data:
  default.conf: |
    server {
      listen 80;
      root /usr/share/nginx/html;
      # THE critical line. Chrome rejects a CRX served as
      # application/octet-stream, and does so without a useful error.
      types { application/x-chrome-extension crx; }
      default_type application/octet-stream;
      location / { autoindex off; }
    }
---
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: utarr-dist
  namespace: downloads
  labels:
    app: utarr-dist
spec:
  accessModes:
    - ReadWriteOnce
  storageClassName: fatboy-nfs-appdata
  resources:
    requests:
      storage: 1Gi
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: utarr-dist
  namespace: downloads
  labels:
    app: utarr-dist
spec:
  replicas: 1
  strategy:
    type: Recreate
  selector:
    matchLabels:
      app: utarr-dist
  template:
    metadata:
      labels:
        app: utarr-dist
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 101
        runAsGroup: 101
        fsGroup: 101
        seccompProfile:
          type: RuntimeDefault
      containers:
        - name: nginx
          image: nginxinc/nginx-unprivileged:1.27-alpine
          ports:
            - name: http
              containerPort: 8080
          securityContext:
            allowPrivilegeEscalation: false
            capabilities:
              drop: ["ALL"]
          volumeMounts:
            - name: html
              mountPath: /usr/share/nginx/html
            - name: conf
              mountPath: /etc/nginx/conf.d
          readinessProbe:
            httpGet: { path: /, port: http }
            periodSeconds: 15
          resources:
            requests:
              cpu: 10m
              memory: 32Mi
            limits:
              memory: 128Mi
      volumes:
        - name: html
          persistentVolumeClaim:
            claimName: utarr-dist

            name: utarr-dist-nginx
---
apiVersion: v1
kind: Service
metadata:
  name: utarr-dist

kind: IngressRoute
metadata:
  name: utarr-dist
  namespace: downloads

    app: utarr-dist

  entryPoints:
    - websecure
  routes:

        - name: utarr-dist

---
apiVersion: traefik.io/v1alpha1
kind: IngressRoute
metadata:
  name: utarr-dist-http
  namespace: downloads
  labels:
    app: utarr-dist
spec:
  entryPoints:
    - web
  routes:
    - match: Host(`utarr-dist.talos00`)

      middlewares:
        - name: redirect-https
          namespace: traefik
      services:
        - name: utarr-dist
```

### Task 13: Policy install on macOS

**Files:** none in either repo — this is an operator action, documented in EXT's `README.md`.

**Interfaces:**
- Consumes: the extension ID (Task 11) and the hosted `updates.xml` (Task 12)
- Produces: the extension installed and auto-updating, with no developer-mode nag

- [ ] **Step 1: Install the policy**

```bash
EXTID=<id from Task 11 Step 2>
sudo defaults write /Library/Preferences/com.google.Chrome ExtensionInstallForcelist \
  -array "$EXTID;https://utarr-dist.talos00/updates.xml"
sudo defaults write /Library/Preferences/com.google.Chrome ExtensionInstallSources \
  -array "https://utarr-dist.talos00/*"
```

The forcelist entry points at the **XML, not the CRX** — a common mistake that fails silently.

- [ ] **Step 2: Restart Chrome and verify**

Fully quit Chrome, reopen, and visit `chrome://policy`. Expected: both policies listed with status OK. Then `chrome://extensions` should show utarr as installed and managed by policy — with no "Disable developer mode extensions" bubble.

If it does not appear, check `chrome://policy` first: a missing policy means the plist did not take; a present policy with no extension means the update XML or the MIME type is wrong.

- [ ] **Step 3: Verify auto-update**

Bump `version` in `manifest.json` to `1.0.1`, run `task release`, republish both files (Task 12 Step 4), then in `chrome://extensions` click **Update**. Expected: utarr moves to 1.0.1.
